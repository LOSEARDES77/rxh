# OIDC Sign-in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People sign in to the dashboard through the organisation's OpenID Connect provider, and get their roles from a claim of the provider.

**Architecture:** `[admin] public_url` and `[admin.oidc]` in `crates/core`. A new `crates/server/src/oidc.rs` does discovery, the authorization code flow with PKCE, `state` and `nonce`, the token exchange over the existing upstream dialer, the ID token claim checks and the role mapping; two routes start and finish the flow and create an ordinary session that carries its roles. The page gets one button. No new dependency.

**Tech Stack:** Rust (hyper, tokio, tokio-rustls through the existing `Dialer`, serde_json, sha2, base64, aws-lc-rs for random bytes), Svelte 5.

**Spec:** `docs/superpowers/specs/2026-11-21-auth-design.md`, section "OIDC" and the `[admin.oidc]` part of "Configuration". The accounts plan (`2026-11-21-accounts.md`) is done; its Global Constraints still bind.

## Global Constraints

- No new crate in `[workspace.dependencies]`.
- The ID token's signature is not checked: it is read only from the token endpoint's answer, over TLS, as OpenID Connect Core 3.1.3.7 allows. An ID token from anywhere else (a query parameter, a fragment) is never accepted.
- Claims checked, all of them, or the sign-in is refused: `iss` equals the configured `issuer` exactly; `aud` is `client_id` or an array containing it (and when the array has more than one entry, `azp` equals `client_id`); `exp` is in the future (60 seconds of clock skew allowed); `nonce` equals the one stored for this flow.
- `issuer`, and every endpoint read from the discovery document, must be `https`, except a loopback address (tests). The discovery document's `issuer` must equal the configured one.
- Every request to the provider goes through the existing `Dialer` (so the admin guard and the trust roots apply), with a 10 second limit and at most 1 MiB of answer.
- A flow is bound to the browser that started it: a cookie set by `GET /auth/oidc/login` must match the pending flow at the callback. Pending flows live 10 minutes, at most 1000, the oldest goes first, and each is used once.
- The flow is offered only where a session cookie is (`peer.tls || peer.local`), and `public_url` is where the provider sends the browser back.
- Secrets (`client_secret`, codes, tokens, PKCE verifiers, `state`, `nonce`) never appear in a response, a log line or `GET /config`; `client_secret` is masked as `***` like the other secrets of the configuration.
- A session made by OIDC carries its roles from sign-in time, lasts 12 hours, and has no password: `PUT /auth/password` answers `403` for it.
- Tests use a fake provider on localhost in `crates/util`; nothing outside localhost.
- Three cargo checks pass at the end of every task; UI tasks also `bun run check`, `bun run test`, `bun run build` with `dist/` committed. Docs move with the code. Branch `auth`; commit after each task; never push.

## Review Focus

1. **Signing in as someone else's flow** (login CSRF): a callback with a valid `code` and `state` of another browser's flow must be refused because the binding cookie is missing or different. Test in Task 2.
2. **A provider that answers wrongly**: no `id_token`, an ID token with a wrong `iss`, `aud`, `nonce` or an expired `exp`, a token endpoint error, a slow or huge answer, a discovery document naming another issuer or an `http` endpoint. Each refuses the sign-in with a page that says so and names nothing secret. Tests in Task 2.
3. **Claims in odd shapes**: `groups` missing, a string instead of a list, a list with non-strings, a name claim missing (falls back to `sub`), names with markup or control characters (shown as text, logged escaped). Tests in Task 2.
4. **A user with no mapped role**: refused with a page naming the user and the groups received, no session. A group mapped to a role that does not exist in the users file gives that role nothing. Tests in Task 2.
5. **Replay**: the same callback URL used twice, a `state` older than 10 minutes, the back button after signing out. Tests in Task 2.

- `Admin::oidc: Option<Oidc>`:

```rust
pub struct Oidc {
    pub issuer: String,                 // https URL, or http on loopback; no trailing slash kept
    pub client_id: String,              // not empty
    pub client_secret: String,          // not empty; masked
    pub scopes: Vec<String>,            // default ["openid", "profile", "email"]; must contain "openid"
    pub groups_claim: String,           // default "groups"
    pub name_claim: String,             // default "preferred_username"
    pub roles: BTreeMap<String, Vec<String>>, // claim value -> role names; names valid by is_group_name or "admin"
}
```

- `oidc` needs `tls` in `[admin]` or a loopback `listen` (a session cookie is not offered otherwise): validation error naming both.

### Task 2: The flow

**Files:** create `crates/server/src/oidc.rs`, `crates/util/src/oidc_provider.rs`, `crates/server/tests/oidc.rs`; modify `crates/server/src/admin.rs` (routes in `ROUTES` as `Audience::Anyone`, `AdminState::oidc: Option<oidc::Client>`), `auth_api.rs`, `daemon.rs`, `lib.rs`, `crates/util/src/lib.rs`, docs, `CHANGELOG.md`

**Interfaces — consumes:** `Sessions::create` (a session with `roles: Some(…)` and no password hash), `session::cookie`, `Peer`, `Dialer` with the admin guard, `Access::scope(&roles)`.

**Interfaces — produces:**

```rust
// oidc.rs
pub(crate) struct Client { /* settings, public_url, dialer(s), discovery cache (1 hour), pending flows */ }
impl Client {
    pub(crate) fn new(settings: &config::Oidc, public_url: &str, guard: AdminGuard) -> io::Result<Self>;
    pub(crate) async fn start(&self) -> Result<Start, Failure>;   // discovery, then the authorization URL
    pub(crate) async fn finish(&self, query: &str, binding: Option<&str>) -> Result<Identity, Failure>;
    pub(crate) fn issuer_host(&self) -> &str;
}
pub(crate) struct Start { pub(crate) location: String, pub(crate) binding: String }
pub(crate) struct Identity { pub(crate) name: String, pub(crate) roles: Vec<String>, pub(crate) groups: Vec<String> }
pub(crate) enum Failure { Provider(String), Refused(String), NoRole { name: String, groups: Vec<String> } }
fn claims_of(id_token: &str) -> Result<serde_json::Value, String>;            // payload of a compact JWT, base64url
fn check_claims(claims: &Value, issuer: &str, client_id: &str, nonce: &str, now: u64) -> Result<(), String>;
fn name_of(claims: &Value, name_claim: &str) -> Option<String>;               // falls back to "sub"
fn groups_of(claims: &Value, groups_claim: &str) -> Vec<String>;              // a string or a list of strings
fn roles_of(groups: &[String], mapping: &BTreeMap<String, Vec<String>>) -> Vec<String>; // union, sorted, no repeats
fn challenge(verifier: &str) -> String;                                       // S256
```

- `rxh_test_util::OidcProvider`: `start() -> OidcProvider` on port 0 over plain HTTP on loopback; `issuer()`; `set_claims(json)`; `set_token_error(status)`; switches for each wrong answer in Review Focus 2; `authorize(location) -> String` plays the browser at the provider and returns the callback URL it would redirect to; it checks `client_secret`, `redirect_uri`, the PKCE verifier against the challenge, and that a code is used once.

**Routes:**
- `GET /auth/oidc/login`: `404` when `[admin.oidc]` is not set; `403` when `!(peer.tls || peer.local)`. Else `302` to the provider's authorization endpoint with `response_type=code`, `client_id`, `redirect_uri={public_url}/auth/oidc/callback`, `scope`, `state`, `nonce`, `code_challenge`, `code_challenge_method=S256`, and `Set-Cookie: rxh_oidc=<binding>; HttpOnly; SameSite=Lax; Path=/; Max-Age=600` (plus `Secure` on TLS).
- `GET /auth/oidc/callback?code=…&state=…` (or `error=…`): checks the binding cookie against the pending flow of `state`, removes the flow, exchanges the code (`POST` form `grant_type=authorization_code`, `code`, `redirect_uri`, `code_verifier`, with HTTP Basic `client_id:client_secret`), checks the claims, maps the roles. On success: creates the session and answers `200` with a small HTML page (`Content-Security-Policy: default-src 'none'`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`) that sets the session cookie, clears `rxh_oidc`, and sends the browser to `{public_url}/dashboard` with `<meta http-equiv="refresh" content="0; url=…">` and a link. Not a `302`: the browser would not send a `SameSite=Strict` cookie on a redirect that began at the provider. On failure: `403` (or `502` for `Failure::Provider`) with a small HTML page saying why in one sentence, with a link back to the dashboard; text escaped; nothing secret.
- `GET /auth/session` now reports `oidc: true` and `oidc_issuer: "<host>"` when configured, and `local: bool` for the signed-in user (false for an OIDC session).
- `PUT /auth/password` with an OIDC session: `403 {"error":"this account signs in through the provider"}`.
- A session with roles: the scope is `Access::scope(&session.roles)` computed on each request from the current users file, so editing or removing a role applies at once; the membership is the one of sign-in time. The `Caller::User` label in logs is `name (oidc)`.
- Log lines: sign-in with name and client address; each refusal with its reason; never a code or token.
