# Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the read only `/dashboard` with a web UI that shows one hour of statistics and edits every configuration key through forms (or TOML), saved to the configuration file and applied with a reload.

**Architecture:** The daemon gains a statistics ring buffer and admin routes that read and write the tables of the configuration files with `toml_edit` (the CLI's `edit.rs`, moved into `crates/server`). A Svelte page, compiled with Bun and committed as `dist/`, is embedded in the binary; its forms are generated from `Config::json_schema()`.

**Tech Stack:** Rust (hyper, tokio, toml_edit, schemars, sha2), Svelte 5, TypeScript, Vite, Vitest, Bun 1.4.

**Spec:** `docs/superpowers/specs/2026-11-20-webui-design.md`

## Global Constraints

- `cargo build`, `cargo install` and package builds never need Bun or Node: Rust embeds the committed `crates/server/ui/dist/`.
- Rust follows `~/.claude/CLAUDE.md` (Google Rust style): no `unwrap` outside tests, no glob imports, `expect("why")`, doc comments on public items.
- Every task ends with `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` passing; UI tasks also `bun run check`, `bun run test`, `bun run build` in `crates/server/ui` with `dist/` committed.
- Tests bind to port 0 or use `rxh_test_util::free_address`; nothing outside localhost.
- Front end: no `innerHTML`, no `{@html}`, no inline `<script>`, no `style=` attributes (the policy is `style-src 'self'`), no request to another origin, no runtime dependency besides `svelte`.
- All API URLs in the page are relative (`status`, not `/status`), so it works behind a path prefix.
- Secrets leave the daemon as `***`; a `***` coming back means "keep what is stored".
- Statistics: one sample every 5 seconds, 720 samples.
- A write that does not validate or does not reload leaves every file byte for byte as it was.
- Work on branch `webui`; commit after each task; never push.

## Review Focus

1. **TOML layouts other than `[upstream.x]` / `[[server]]`** (inline `server = [{...}]`, dotted keys `upstream.api.policy = "..."`, inline table pools): the entity list must show them and a save must not duplicate or drop them. Test in Task 2.
2. **Names with dots, quotes, spaces or markup** (`[upstream."a.b"]`, a Docker host named `<img onerror=…>`): routes address them percent encoded, the page shows them as text. Tests in Tasks 4 and 9.
3. **Configuration file or directory not writable**: the write answers an error naming the file, no `.tmp` is left, the daemon keeps serving the old configuration. Test in Task 5.
4. **Counters that go backwards or series that appear and vanish** (pool removed by a reload, first sample, empty history): rates are never negative or `NaN`, charts show "no data". Tests in Tasks 6 and 8.
5. **Token wrong or changed while a form is open** (401 on save): the page asks for the token again and the form keeps what was typed. Test in Task 7.

  #[serde(rename_all = "lowercase")]
  pub(crate) enum Kind { Server, Upstream, Section }
  impl Kind { pub(crate) fn from_segment(segment: &str) -> Option<Self>; }

  #[derive(Debug, Serialize)]

  /// Sections that are tables, in display order; "top" is the bare keys of the root.
  pub(crate) const SECTIONS: [&str; 10] =

  pub(crate) fn list(file_index: usize, document: &DocumentMut) -> Vec<Entity>;

  pub(crate) fn remove(document: &mut DocumentMut, kind: Kind, key: &str) -> Result<(), String>;

- Merge rule of `replace_value`: a key whose JSON value equals the current value is not touched (comment and formatting kept); a different value is set; a key missing from the JSON is removed; a JSON object merges into an existing table by the same rule; arrays are replaced whole. ### Task 5: Write routes with validation, reload and rollback

**Files:**
- Modify: `crates/server/src/config_api.rs`, `crates/server/src/admin.rs`, `crates/server/tests/config_edit.rs`

**Interfaces:**
- Consumes: Tasks 1 to 4; `admin::control(&state, Control::Reload, "saved")` (make `control` `pub(crate)`); `MAX_CONFIG_BODY`.
- Produces the routes (bodies are JSON):
  | Route | Body | Success |
  |---|---|---|
  | `PUT /config/files/{index}` | `{ "text": "...", "revision": "..." }` | `200 { "saved": true }` |
  | `POST /config/entities/{kind}` | `{ "value": {…} \| "toml": "...", "key": "name"?, "file": 0? }` | `201 { "key": "..." }` |
  | `PUT /config/entities/{kind}/{key}` | `{ "value": {…} \| "toml": "...", "revision": "..." }` | `200 { "saved": true }` |
  | `DELETE /config/entities/{kind}/{key}?revision=...` | none | `200 { "saved": true }` |
- `{key}` is percent decoded by the existing segment decoding; a server key is `file:position`; a pool or section is looked up in every file, first match.
- One private function does every write:
  ```rust
  /// Opens the files, checks `revision` of file `index`, applies `change`, restores
  /// masked secrets, saves, reloads, and puts the files back if the reload fails.
  async fn save(state: &AdminState, index: usize, revision: Option<&str>,
                change: impl FnOnce(&mut ConfigFile) -> Result<(), String> + Send + 'static)
      -> Result<(), (StatusCode, String)>;
  ```
- Status codes: `409` no configuration file, or `revision` differs (`"the file changed, read it again"`); `404` unknown file index, kind, or key; `400` body not JSON, both or neither of `value`/`toml`, validation failure (text from `save_all`), reload failure (text from the daemon, after `edit::restore`); `500` a file cannot be written or restored.
- `revision` is required on `PUT` and `DELETE`, not on `POST`.
- A second writer is excluded with a `tokio::sync::Mutex<()>` in `AdminState` (`saving`) held across `save`.
- The daemon's watcher already ignores the reload it is told about (`Watcher::loading`, `daemon.rs:284`); no extra work for `watch = true`, but test it.
